## Chunk Vectorisation（分片向量化）

### 一、定义与核心目标

**Chunk Vectorisation** 是将文本分片（Chunks）转换为数值向量（Vectors）的关键步骤，目的是让计算机能够理解文本的语义，并通过向量之间的相似性进行高效检索。

**核心目标**：
- 将人类可读的文本转换为机器可理解的数值表示
- 最大化向量对语义的表征能力，使语义相似的文本在向量空间中距离更近
- 支持高效的相似度计算和快速检索，为 RAG 系统的检索召回阶段提供基础

**在 RAG 流程中的位置**：
```
Data Chunking → Chunk Vectorisation → Vector Data Store → Data Retrieval
```

---

### 二、向量化算法分类

向量化算法（模型）主要分为两大类：

| 类别 | 代表模型 | 特点 | 适用场景 |
|------|----------|------|----------|
| **传统文本嵌入算法** | BoW、TF-IDF、Word2Vec、GloVe、FastText | 基于统计或浅层神经网络，计算效率高 | 简单场景、低资源环境 |
| **基于预训练语言模型的嵌入算法** | BERT、Sentence-BERT、USE、BGE、E5、Longformer、gte-large | 基于深层 Transformer 架构，语义理解能力强 | RAG 系统主流选择 |

### 三、传统文本嵌入算法

#### 1. 词袋模型（Bag of Words, BoW）及衍生

**原理**：将文本视为词语的无序集合，统计词语出现频率作为向量特征。

**变种**：
- **独热编码（One-Hot Encoding）**：每个词用唯一的向量表示，向量维度等于词汇表大小
- **词频向量（TF Vector）**：统计每个词在文档中出现的次数

**局限**：
- 忽略词语顺序和语义关联
- 向量维度高（等于词汇表大小），易导致维度灾难
- 无法区分多义词的不同含义

**衍生算法 - TF-IDF**：
- **原理**：通过权衡词语在文档和语料库中的重要性优化向量
- **计算公式**：`TF-IDF(w, d) = TF(w, d) × IDF(w)`
  - TF（词频）：词语在文档中出现的频率
  - IDF（逆文档频率）：衡量词语在整个语料库中的稀有程度
- **优势**：降低常用词（如"的"、"是"）的权重，突出关键词
- **应用**：信息检索领域的经典方法，如搜索引擎

#### 2. Word2Vec

**原理**：通过浅层神经网络学习词语的分布式表示，将词语映射到低维向量空间。

**两种训练模式**：
- **CBOW（Continuous Bag of Words）**：用上下文预测中心词
- **Skip-gram**：用中心词预测上下文

**核心特性**：
- 向量相似度可反映语义相关性（如 "国王 - 男人 + 女人 ≈ 女王"）
- 向量维度通常为 100-300 维，远低于独热编码
- 捕获词语的句法和语义关系

**局限**：
- 仅支持词语级向量，需通过拼接/平均等方式生成句子/文档向量
- 无法处理多义词和上下文变化（静态词向量）
- 对否定词和复杂语义表达能力有限

#### 3. GloVe（Global Vectors for Word Representation）

**原理**：结合全局词频统计和局部上下文信息，通过最小化词向量与共现概率的误差学习表示。

**核心思想**：
- 统计词语在上下文窗口内的共现频率
- 构建词-词共现矩阵
- 通过矩阵分解学习词向量

**优势**：
- 兼顾 Word2Vec 的局部语境和全局统计特性
- 训练效率高于 Word2Vec
- 向量质量稳定

**局限**：
- 仍为静态词向量，无法处理多义词
- 需进一步处理为长文本向量

#### 4. FastText

**原理**：在 Word2Vec 基础上引入"子词（n-gram）"机制。

**核心创新**：
- 将词语拆分为字符级子词（如 "apple" 拆分为 "app"、"ple"）
- 词向量由其包含的子词向量之和表示

**优势**：
- 支持未登录词（OOV）的向量生成
- 适合多语言或拼写不规则的场景
- 对形态丰富的语言（如德语）效果更好
- 模型训练速度快

**局限**：
- 子词粒度较细，可能引入噪声
- 语义理解能力仍有限

### 四、基于预训练语言模型（LLM）的嵌入算法

这类算法基于深层 Transformer 架构，通过大规模语料预训练学习上下文语义，能生成高质量的句子/文档级向量，是当前 RAG 系统的主流选择。

#### 1. BERT 及衍生模型

**BERT（Bidirectional Encoder Representations from Transformers）**：

**原理**：通过双向 Transformer 学习上下文依赖的词语表示。

**生成句子嵌入的方式**：
- 使用 `[CLS]` 标记的隐藏状态作为句子嵌入
- 对所有 token 的向量取平均作为句子嵌入

**局限**：
- 原始 BERT 未专门优化句子级表征，效果较差
- 相似度计算效率低（需对每个句子对单独编码）

**衍生模型**：

##### Sentence-BERT（SBERT）

**核心改进**：针对句子嵌入优化的 BERT 变体，通过对比学习使相似句子的向量更接近。

**训练方法**：
- 使用三元组损失（Triplet Loss）进行对比学习
- 构建"锚点-正例-负例"三元组训练样本
- 目标：让锚点与正例的距离 < 锚点与负例的距离 + 边际

**优势**：
- 支持高效的句子级相似度计算，速度比原生 BERT 快 100 倍以上
- 语义对齐更精准，能处理复杂语义关系
- 支持多语言模型，如 `paraphrase-multilingual-mpnet-base-v2`

**适用场景**：RAG 中最常用的模型之一，适合中小规模文本的实时检索

##### MiniLM

**特点**：轻量级 BERT 变体，参数更小。

**代表模型**：
- `MiniLM-L6-H384`：仅 660 万参数
- `all-MiniLM-L6-v2`：轻量高效，适合实时检索

**优势**：
- 参数量小，推理速度快
- 性能接近 SBERT，适合资源受限场景

#### 2. 通用句子嵌入模型

##### Sentence Transformers 库中的模型

| 模型名称 | 特点 | 适用场景 |
|----------|------|----------|
| `all-MiniLM-L6-v2` | 轻量高效，向量维度 384 | 实时检索、多语言场景 |
| `all-mpnet-base-v2` | 性能更强，向量维度 768 | 高精度语义检索 |
| `all-distilroberta-v1` | 蒸馏版，平衡性能与效率 | 中等规模应用 |
| `paraphrase-multilingual-mpnet-base-v2` | 多语言支持 | 跨语言检索 |

##### USE（Universal Sentence Encoder）

**特点**：谷歌推出的通用句子编码器。

**版本**：
- **轻量版**：基于 Transformer 架构，适合精度要求较高的场景
- **高效版**：基于 DAN（Deep Averaging Network）架构，推理速度更快

**优势**：
- 支持多种输入（句子、短语）
- 适合跨语言场景
- 模型轻量，部署方便

##### BGE 系列（中文 RAG 天花板）

**特点**：由北京智源研究院（BAAI）开源的中文嵌入模型系列，是目前国内 RAG 场景中最主流的选择，被称为"中文 RAG 天花板"。

**核心模型**：

| 模型名称 | 向量维度 | 特点 |
|----------|----------|------|
| `bge-base-zh` | 768 | 基础版，中文语义理解能力强 |
| `bge-large-zh` | 1024 | 大模型版，精度更高，适合高精度场景 |
| `bge-small-zh` | 512 | 轻量版，推理速度快，适合资源受限场景 |
| `bge-m3` | 1024 | 多任务模型，支持检索、聚类、分类等多种任务 |

**核心优势**：
- **中文语义理解顶尖**：在中文数据集上的表现超过大多数国外模型
- **多任务能力强**：bge-m3 支持多种下游任务，无需额外微调
- **训练数据丰富**：基于大规模中文语料训练，覆盖多领域知识
- **开源免费**：完全开源，可自由商用

**适用场景**：
- 中文 RAG 系统（国内企业首选）
- 中文语义检索、问答系统
- 跨语言检索（支持中英双语）

**使用建议**：
- 生产环境首选 `bge-large-zh` 或 `bge-m3`
- 资源受限场景选择 `bge-small-zh`
- 配合 BGE Reranker 使用，可进一步提升检索精度

##### E5 系列（工业 RAG 标杆）

**特点**：由微软研究院开源的嵌入模型系列，以其优异的性能和工业级稳定性著称，被称为"工业 RAG 标杆"。

**核心模型**：

| 模型名称 | 向量维度 | 特点 |
|----------|----------|------|
| `e5-base` | 768 | 基础版，平衡性能与效率 |
| `e5-large` | 1024 | 大模型版，精度更高 |
| `e5-small` | 384 | 轻量版，速度极快 |
| `e5-base-v2` | 768 | 升级版，性能进一步提升 |
| `e5-mistral-7b-instruct` | 4096 | 基于 Mistral 的大模型，支持超长上下文 |

**核心优势**：
- **工业级稳定性**：经过大规模工业场景验证，性能稳定可靠
- **多语言支持**：支持 100+ 种语言，适合全球化应用
- **指令微调优化**：通过指令微调提升检索性能，支持自然语言指令
- **微软背书**：由微软研究院开发维护，技术支持有保障

**训练创新**：
- 使用"指令对比学习"（Instruction-tuned Contrastive Learning）
- 将检索任务转化为指令形式，提升模型对复杂查询的理解能力
- 支持多种检索模式（如语义检索、关键词检索、混合检索）

**适用场景**：
- 工业级 RAG 系统
- 多语言检索场景
- 企业级知识库系统
- 需要高稳定性的生产环境

**使用建议**：
- 通用场景首选 `e5-base-v2`
- 高精度要求选择 `e5-large` 或 `e5-mistral-7b-instruct`
- 实时检索场景选择 `e5-small`

#### 3. 长文本专用嵌入模型

**挑战**：传统 LLM 对长文本（如超过 512 tokens）处理能力有限。

**解决方案**：通过优化注意力机制或分段聚合支持更长输入。

**代表模型**：

| 模型名称 | 最大输入长度 | 特点 |
|----------|--------------|------|
| `gte-large` | 8192 tokens | 开源模型，针对长文本优化 |
| `Longformer` | 4096 tokens | 通过稀疏注意力机制支持超长文本 |
| `Cohere Command` | 2048 tokens | 商业模型，语义理解能力强 |
| `Llama 2` | 4096/70000 tokens | 开源模型，支持超长上下文 |

**长文本处理策略**：
- **分段编码**：将长文本切分为多个片段，分别编码后聚合
- **稀疏注意力**：只计算关键 token 之间的注意力，降低复杂度
- **滑动窗口**：用固定窗口遍历长文本，保留局部上下文信息

#### 4. 多模态嵌入模型

**适用场景**：RAG 系统涉及图片、表格等多模态数据。

**代表模型**：

##### CLIP（Contrastive Language-Image Pretraining）

**原理**：将文本和图片映射到同一向量空间。

**功能**：
- 支持"文本检索图片"或"图片检索文本"
- 无需额外标注，通过对比学习自动对齐文本和图像

**应用场景**：
- 图文混合文档的检索
- 视觉问答系统

##### BLIP-2

**原理**：通过桥接模型连接视觉编码器和语言模型。

**特点**：
- 生成多模态嵌入向量
- 支持更复杂的图文交互任务
- 适合图文混合文档的向量化

### 五、向量相似度计算方法

向量化后，需要通过相似度计算衡量文本之间的语义相关性。

#### 常用相似度度量

| 方法 | 公式 | 特点 |
|------|------|------|
| **余弦相似度** | $cos(θ) = \frac{A \cdot B}{\|A\| \times \|B\|}$ | 衡量方向相似性，不受向量长度影响，最常用 |
| **欧氏距离** | $L2 = \sqrt{\|A - B\|^2}$ | 衡量空间距离，距离越小越相似 |
| **曼哈顿距离** | $L1 = \sum_{i=1}^n \|A_i - B_i\|$ | L1 距离，计算简单 |
| **点积** | $IP = \sum_{i=1}^n a_i \cdot b_i$ | 计算效率高，但受向量长度影响 |

#### 在 RAG 中的应用

1. **检索阶段**：计算查询向量与所有存储向量的相似度，返回 Top-K 最相似的分片
2. **重排序阶段**：对召回的分片进行更精细的相似度计算，优化排序结果

### 六、算法选择建议

#### 根据场景选择

| 场景 | 推荐模型 | 理由 |
|------|----------|------|
| **中小规模文本、实时性要求高** | Sentence-BERT（如 `all-MiniLM-L6-v2`）、USE 轻量版、`bge-small-zh`、`e5-small` | 轻量高效，响应快 |
| **长文本（如论文、报告）** | `gte-large`、Longformer、Cohere Command、`e5-mistral-7b-instruct` | 支持长上下文，语义理解强 |
| **多语言场景** | `paraphrase-multilingual-mpnet-base-v2`、USE 多语言版、E5 系列 | 支持多种语言 |
| **低资源环境** | FastText、MiniLM、`bge-small-zh`、`e5-small` | 模型小，推理快 |
| **高精度要求** | `all-mpnet-base-v2`、OpenAI Embeddings、`bge-large-zh`、`e5-large` | 语义捕捉更精准 |
| **多模态数据** | CLIP、BLIP-2 | 支持图文混合 |
| **中文 RAG 场景** | **BGE 系列**（`bge-large-zh`、`bge-m3`） | 中文语义理解顶尖，国内主流选择 |
| **工业级 RAG 场景** | **E5 系列**（`e5-base-v2`、`e5-large`） | 工业级稳定性，多语言支持 |

#### 根据资源约束选择

| 资源级别 | 推荐方案 |
|----------|----------|
| **CPU 环境** | `all-MiniLM-L6-v2`、USE 高效版、FastText、`bge-small-zh`、`e5-small` |
| **GPU 环境** | `all-mpnet-base-v2`、`gte-large`、Sentence-BERT 全量模型、`bge-large-zh`、`e5-large` |
| **无本地部署** | OpenAI Embeddings API、Cohere API |

### 八、实践要点

#### 1. 向量维度选择

- **低维度（128-384）**：适合快速检索、存储成本低，但语义表征能力有限
- **中维度（512-768）**：平衡性能与精度，是大多数场景的选择
- **高维度（1024+）**：语义捕捉更精准，但计算和存储成本较高

#### 2. 批处理优化

- 将多个文本分片批量编码，提高 GPU 利用率
- 设置合理的 batch size，避免显存溢出

#### 3. 缓存策略

- 对已向量化的文本建立缓存，避免重复计算
- 使用 Redis 等内存数据库存储高频访问的向量

#### 4. 模型微调

- 在特定领域数据上微调嵌入模型，提升领域适配能力
- 使用对比学习方法，在领域数据上重新训练模型

#### 5. 评估指标

- **语义相似度任务**：STS-B 数据集的 Pearson/Spearman 相关系数
- **检索任务**：Recall@K、NDCG（归一化折损累积增益）
- **分类任务**：准确率、F1 值

### 九、总结

在 RAG 系统中，向量化算法的核心目标是最大化向量对语义的表征能力，从而提升检索精度。实际应用中，需根据以下因素选择合适的模型：

1. **文本长度**：短文本用轻量模型，长文本用专用模型
2. **资源限制**：CPU 环境选择轻量模型，GPU 环境可选择性能更强的模型
3. **多模态需求**：涉及图片等非文本数据时选择多模态模型
4. **精度要求**：高精度场景选择大型模型或商业 API

**当前主流方案**：
- **开源首选**：Sentence-BERT 系列（如 `all-MiniLM-L6-v2`、`all-mpnet-base-v2`）
- **中文 RAG 首选**：BGE 系列（`bge-large-zh`、`bge-m3`），中文语义理解顶尖
- **工业级首选**：E5 系列（`e5-base-v2`、`e5-large`），工业级稳定性
- **商业首选**：OpenAI Embeddings（`text-embedding-ada-002`）
