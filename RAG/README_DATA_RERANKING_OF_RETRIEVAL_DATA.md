## Reranking of Retrieval Data（召回数据重排）

### 一、核心概念与定位

**重排（Reranking）**是对初步检索返回的 Top-K 结果进行重新排序的过程，目的是进一步提升检索结果的相关性和准确性。

**在 RAG 流程中的位置**：
```
Data Chunking → Chunk Vectorisation → Vector Data Store → Data Retrieval → Reranking → LLM Query Generation
```

**核心目标**：
- **提升精度**：将真正相关的文档排在前面
- **降低噪声**：过滤掉不相关或低相关的文档
- **优化排序**：根据更精细的相似度计算重新排序

**为什么需要重排**：
- 向量检索是近似搜索，可能存在误差
- 初步检索返回的结果可能包含噪声
- 需要更精细的语义匹配来确定最终排序

---

### 二、重排流程详解

#### 标准重排流程

```
初步检索（Top-50）→ 重排模型打分 → 过滤低分数文档 → 重新排序 → 返回最终结果（Top-K）
```

#### 各阶段说明

##### 1. 初步检索

从向量数据库中检索更多的候选结果（通常 Top-50~100）。

##### 2. 重排模型打分

使用专门的重排模型对每个候选文档进行打分。

##### 3. 过滤低分数文档

根据阈值过滤掉分数过低的文档。

##### 4. 重新排序

按重排分数从高到低排序。

##### 5. 返回最终结果

返回重排后的前 K 个结果（通常 K=3~10）。

---

### 三、重排模型详解

#### 1. CrossEncoder（交叉编码器）

**原理**：将查询和文档拼接在一起输入模型，直接预测它们之间的相关性分数。

**特点**：
- 优点：语义理解能力强，排序精度高
- 缺点：计算成本高（需要为每个候选文档单独计算）
- 速度：较慢

**代表模型**：

| 模型名称 | 参数量 | 特点 | 适用场景 |
|----------|--------|------|----------|
| cross-encoder/ms-marco-MiniLM-L-6-v2 | 660万 | 轻量高效 | 通用场景、实时检索 |
| cross-encoder/ms-marco-MpNet-base-v2 | 110M | 精度更高 | 高精度要求场景 |
| BAAI/bge-reranker-base | 110M | 中文优化 | 中文 RAG 场景 |
| BAAI/bge-reranker-large | 340M | 高精度中文 | 高精度中文场景 |

#### 2. BiEncoder（双编码器）

**原理**：分别编码查询和文档，然后计算它们的向量相似度。

**特点**：
- 优点：计算效率高，支持预计算
- 缺点：语义理解能力相对较弱
- 速度：快

**适用场景**：初步检索阶段

#### 3. CrossEncoder vs BiEncoder 对比

| 维度 | CrossEncoder | BiEncoder |
|------|--------------|-----------|
| 精度 | 高 | 中 |
| 速度 | 慢 | 快 |
| 计算成本 | 高 | 低 |
| 适用阶段 | 重排阶段 | 检索阶段 |

### 四、重排策略详解

#### 1. 单阶段重排

对初步检索结果直接进行一次重排。

**优点**：实现简单，计算成本可控
**缺点**：可能漏掉某些相关文档
**适用场景**：大多数 RAG 系统

#### 2. 多阶段重排

使用多个重排模型进行级联排序。

**流程**：初步检索（Top-100）→ 轻量重排（Top-20）→ 重量级重排（Top-10）

**优点**：精度更高，平衡速度和精度
**缺点**：实现复杂，计算成本更高
**适用场景**：对精度要求极高的场景

#### 3. 混合重排

结合向量相似度和重排分数进行综合排序。

**公式**：最终分数 = α × 向量相似度 + β × 重排分数

**优点**：兼顾向量检索的召回和重排的精度
**缺点**：需要调优权重参数
**适用场景**：需要平衡召回和精度的场景

#### 4. 动态阈值重排

根据查询类型动态调整重排策略。

**策略**：简单查询跳过重排或使用轻量重排，复杂查询使用完整重排流程。

**优点**：优化性能，降低不必要的计算
**缺点**：需要判断查询复杂度
**适用场景**：对延迟敏感的场景

---

### 五、重排优化技巧

#### 1. 候选数量优化

- 初步检索：Top-30~100
- 最终返回：Top-3~10

#### 2. 模型选择优化

| 场景 | 推荐模型 | 理由 |
|------|----------|------|
| 实时检索 | ms-marco-MiniLM-L-6-v2 | 轻量高效 |
| 中文场景 | bge-reranker-base | 中文优化 |
| 高精度要求 | ms-marco-MpNet-base-v2 | 精度更高 |
| 无本地部署 | Cohere Rerank API | 无需部署 |

#### 3. 分数归一化

对重排分数进行归一化处理，便于跨模型比较和设置阈值。

#### 4. 缓存优化

对重复查询的重排结果进行缓存，降低重复计算。

---

### 六、重排评估指标

| 指标 | 定义 | 优化目标 |
|------|------|----------|
| NDCG@K | 归一化折损累积增益 | 最大化 |
| MRR | 平均倒数排名 | 最大化 |
| MAP@K | 平均准确率均值 | 最大化 |
| Precision@K | 前 K 个结果中相关文档的比例 | 最大化 |

---

### 七、实践最佳实践

#### 1. 重排链路设计

**推荐架构**：
```
初步检索（Top-50）→ 去重 → 轻量重排（MiniLM）→ Top-20 → 重量级重排（MpNet/BGE-Reranker）→ Top-10 → 返回最终结果
```

#### 2. 参数调优指南

| 参数 | 推荐范围 |
|------|----------|
| 初步检索 K | 30~100 |
| 最终返回 K | 3~10 |
| 重排阈值 | 0~0.5 |
| 向量相似度权重 | 0.1~0.5 |
| 重排分数权重 | 0.5~0.9 |

#### 3. 故障排查

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 重排后精度下降 | 重排模型不合适 | 更换更合适的重排模型 |
| 重排耗时过长 | 候选数量太多 | 减少初步检索的 K 值 |
| 相关文档被过滤 | 阈值设置过高 | 降低重排阈值 |
| 排序不稳定 | 模型分数波动 | 使用混合排序或增加候选数量 |

---

### 八、总结

**核心要点**：
1. 重排目的：提升检索精度，降低噪声
2. 重排模型：CrossEncoder 是主流选择，BGE-Reranker 适合中文场景
3. 重排策略：单阶段重排是基础，多阶段重排和混合重排能提升效果
4. 优化技巧：合理设置候选数量、选择合适模型、使用缓存
5. 评估指标：NDCG@K、MRR 是核心评估指标

**推荐组合**：
- 通用场景：ms-marco-MiniLM-L-6-v2 + Top-50 候选 + Top-10 返回
- 中文场景：bge-reranker-base + 混合排序
- 高精度场景：多阶段重排（MiniLM → MpNet）
- 快速
