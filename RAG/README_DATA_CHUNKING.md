## Data Chunking（数据分片）

### 一、核心原理与技术目标

**Data Chunking** 是将原始文档分割为语义独立文本块的过程，其本质是在**信息完整性**与**计算效率**间寻求平衡。

**在 RAG 流程中的位置**：
```
原始文档 → Data Chunking → Chunk Vectorisation → Vector Data Store
```

**理想分块需满足的四大原则**：

| 原则 | 描述 | 示例 |
|------|------|------|
| **语义自洽性** | 每个块包含完整逻辑单元 | 概念定义、事件描述、完整段落 |
| **检索适配性** | 块大小匹配向量模型输入限制 | 通常 100-500 tokens，具体取决于模型 |
| **上下文延续性** | 关键关联信息不因分割丢失 | 相邻块之间保留重叠区域 |
| **结构完整性** | 保持文档的自然结构边界 | 按段落、章节、标题分割 |

**典型反例**：将技术文档的「配置步骤」与「错误解决方案」切分到不同块，导致检索结果缺乏操作上下文。

### 二、主流分块策略及适用场景

#### 1. 固定窗口分块（Fixed Window Chunking）

**原理**：按固定字符数或 token 数切割文档。

**参数**：
- 块大小：通常 256-512 tokens
- 重叠率：10%-15%（防止语义割裂）

**优势**：
- 实现简单，计算效率高
- 结果可预测，易于调试

**劣势**：
- 可能在语义边界处切割，导致信息碎片化
- 无法适应不同类型文档的需求

**适用场景**：标准化文档（新闻、公告、普通文章）

#### 2. 语义感知分块（Semantic-Aware Chunking）

**原理**：基于语义边界检测进行分割，而非简单的字符计数。

**方法**：
- 基于标点符号分割（优先在句号、分号处分割）
- 基于段落结构分割（按空行、段落标记分割）
- 基于 HTML/XML 标签分割（利用文档结构信息）
- 结合 NLP 断句模型（如 spaCy、HanLP）

**优势**：
- 保持语义完整性，减少信息割裂
- 更符合人类阅读习惯

**劣势**：
- 规则预定义成本高
- 对无结构文本效果有限

**适用场景**：技术手册、学术论文、结构化文档

#### 3. 滑动窗口分块（Sliding Window Chunking）

**原理**：使用固定大小的窗口在文档上滑动，相邻块之间保留重叠区域。

**参数**：
- 窗口大小：即块大小，通常 256-512 tokens
- 滑动步长：小于窗口大小，决定重叠程度
- 重叠比例：通常 10%-20%

**优势**：
- 确保关键信息不被遗漏
- 适合处理连贯的长文本

**劣势**：
- 存储冗余，增加向量数据库负担
- 检索时可能返回重复信息

**适用场景**：连贯长文本（小说、报告、连续叙述性内容）

#### 4. 递归分层分块（Recursive Hierarchical Chunking）

**原理**：先按粗粒度分割（如章节），再对长块进行二次细粒度分割。

**流程**：
1. 按章节/标题分割为大段
2. 对超过阈值的大段进行二次分割
3. 保持层级关系，便于后续检索时重组上下文

**优势**：
- 实现复杂文档的层次化管理
- 支持多粒度检索，兼顾精度和召回

**劣势**：
- 实现复杂，需要理解文档结构
- 计算成本较高

**适用场景**：书籍、研究报告、长篇技术文档

#### 5. 内容驱动分块（Content-Driven Chunking）

**原理**：根据内容类型差异化切割策略。

**策略**：
- **文本**：按语义边界分割
- **表格**：保持表格结构完整性，禁止跨表切割
- **代码**：按函数/类定义分割，保留 import 上下文
- **图片**：将图片描述与邻近文本合并为多模态块

**优势**：
- 针对不同内容类型优化分割策略
- 保持特殊内容的结构完整性

**劣势**：
- 需布局识别技术支撑
- 实现复杂度较高

**适用场景**：混合格式文档（产品说明书、技术文档、PDF 报告）

#### 分块策略对比表

| 策略 | 优点 | 缺点 | 适用场景 | 推荐工具 |
|------|------|------|----------|----------|
| 固定窗口分块 | 简单高效 | 语义割裂 | 新闻、公告 | LangChain CharacterTextSplitter |
| 语义感知分块 | 语义完整 | 规则复杂 | 技术手册、论文 | LlamaIndex SemanticSplitter |
| 滑动窗口分块 | 信息完整 | 存储冗余 | 小说、报告 | LangChain RecursiveCharacterTextSplitter |
| 递归分层分块 | 层次化管理 | 实现复杂 | 书籍、研究报告 | LlamaIndex HierarchicalNodeParser |
| 内容驱动分块 | 差异化处理 | 需要布局识别 | 混合格式文档 | Unstructured.io |

### 三、关键参数与配置建议

#### 1. 块大小（Chunk Size）

**推荐范围**：

| 文档类型 | 推荐块大小 | 理由 |
|----------|------------|------|
| 短文本（FAQ、问答） | 100-200 tokens | 精准匹配用户查询 |
| 普通文章（新闻、博客） | 256-384 tokens | 平衡精度与召回 |
| 技术文档（手册、API） | 384-512 tokens | 保留完整技术上下文 |
| 长文档（论文、报告） | 512-1024 tokens | 保持段落完整性 |

**注意事项**：
- 块大小不应超过嵌入模型的最大输入长度
- 对于支持长上下文的模型（如 gte-large 支持 8192 tokens），可适当增大块大小
- 块太小会导致信息碎片化，块太大则会降低检索精度

#### 2. 重叠策略（Overlap Strategy）

**推荐重叠率**：10%-20%

**重叠的作用**：
- 防止语义边界处的信息丢失
- 保持上下文连续性
- 提高检索召回率

**动态调整策略**：
- 对于语义连贯的文本（如小说），可适当降低重叠率（10%）
- 对于信息密度高的文本（如技术文档），可适当提高重叠率（15%-20%）

#### 3. 分隔符优先级

**推荐优先级**：
1. **Markdown 标题**（`##`、`###`）
2. **段落分隔**（空行）
3. **标点符号**（句号、分号、换行符）
4. **字符/Token 计数**（兜底策略）

### 四、前沿优化技术

#### 1. 动态分块引擎

##### Meta-Chunking
- **原理**：训练轻量模型预测最优分块参数
- **示例**：金融报告需 300±50 tokens，技术文档需 400±50 tokens
- **优势**：根据文档类型自动调整分块策略

##### Late Chunking
- **原理**：延迟分块至检索阶段，根据查询动态调整分块粒度
- **优势**：文档越长越有效，能保留更多上下文信息
- **适用场景**：超长文档处理

#### 2. 语义边界检测增强

##### 基于句嵌入的分割
- **原理**：使用句嵌入模型（如 bge-M3、Sentence-BERT）计算相邻句子的向量相似度，在向量距离骤增点分割
- **优势**：更精确地识别语义边界
- **工具**：LlamaIndex SemanticSplitter

##### 结构感知分块
- **原理**：识别标题层级、Markdown 标签、HTML 结构，优先在自然边界处分块
- **优势**：保持文档的逻辑结构
- **工具**：LangChain MarkdownHeaderTextSplitter

#### 3. 多模态分块

##### 图文联合分块
- **原理**：将图片描述（由视觉模型生成）与邻近文本合并为多模态块
- **优势**：保留图文关联信息

##### 表格特殊处理
- **原理**：保持表格结构完整性，禁止跨表切割
- **工具**：Unstructured.io、Azure AI Document Intelligence

### 六、实践建议与避坑指南

#### 1. 分步调优流程

```
分析文档结构 → 选择基础策略 → 小样本测试 → 评估召回率
                                                    ↓
                                           ┌────────┴────────┐
                                           ↓                 ↓
                                      达标 → 生产部署    未达标 → 调整重叠率/边界规则
```

#### 2. 高频陷阱应对

| 问题 | 解决方案 | 推荐工具 |
|------|----------|----------|
| **表格断裂** | 识别表格区域，保持表格完整性 | Unstructured.io、Azure AI Document Intelligence |
| **代码碎片化** | 按函数/类定义分块，保留 import 上下文 | LangChain PythonCodeTextSplitter |
| **跨页信息割裂** | PDF 解析时启用跨页内容合并 | PyMuPDF、pdfplumber |
| **长段落切割** | 使用语义感知分块，优先在段落边界分割 | LlamaIndex SemanticSplitter |
| **多语言混杂** | 根据语言类型采用不同分词策略 | spaCy 多语言模型 |

#### 3. 生产环境最佳实践

1. **预处理阶段**：对文档进行清洗，移除无关内容（页眉、页脚、广告）
2. **分块策略选择**：根据文档类型选择合适的策略，可混合使用多种策略
3. **块元数据**：为每个块添加元数据（来源、标题、位置、标签），便于后续过滤和检索
4. **质量监控**：定期评估分块质量，根据实际效果调整参数
5. **缓存机制**：对已分块的文档建立缓存，避免重复处理

### 八、开源项目推荐

#### 1. Awesome-Chunker
一站式聚合并复现了当下主流的文本分块技术，包含：
- 经典分块方法：基于字符分割、文档特定分割、递归字符文本分割
- 语义分块：基于 Sentence Transformer 的语义相似度聚类和合并
- Dense X Retrieval：以"命题"作为新的搜索单元进行分块
- LumberChunker：借助大语言模型的理解能力动态分割文档
- Meta-Chunking：通过句子之间的困惑度动态调整窗口大小

#### 2. Chonkie
为 RAG 任务设计的轻量级文本分块库，特点：
- 通过 Tiktoken、预计算缓存等技术实现高效分块
- 性能远超竞争对手
- 简单易用，API 友好

#### 3. Late Chunking
延迟分块策略的实现，特点：
- 先进行全面处理再分类整理
- 利用长上下文 Embedding 模型切分块
- 文档越长效果越优

#### 4. ChunkRAG
改进版 RAG 框架，特点：
- 显著改进块级别过滤和细粒度相关性评估
- 将文本划分为语义上有意义的块
- 减少生成不相关或幻觉信息的情况

#### 5. SLM-qwen0.5
基于 Qwen 的轻量级分块模型系列，包括：
- **simple-qwen-0.5**：基于文档的结构元素识别边界
- **topic-qwen-0.5**：识别文本中的主题来定义分块边界
- **summary-qwen-0.5**：不仅识别边界，还为每个块生成摘要

### 九、总结

通过定向优化分块策略，可显著提升 RAG 系统的召回精度，最高可降低 LLM 幻觉率 35%。

**核心要点**：
1. **选择合适的分块策略**：根据文档类型和应用场景选择
2. **合理设置块大小和重叠率**：平衡信息完整性和计算效率
3. **利用语义感知技术**：提升分块质量
4. **关注特殊内容处理**：表格、代码、图片等需要特殊处理
5. **持续评估和调优**：根据实际效果不断优化

**推荐组合**：
- **通用场景**：LangChain RecursiveCharacterTextSplitter + 256-512 tokens + 15% 重叠
- **高精度场景**：LlamaIndex SemanticSplitter + 语义边界检测
- **复杂文档**：Unstructured.io + 内容驱动分块
